# 可复用技能制作

将真实工作流整理为能被另一个 Agent 正确选择、执行和验证的技能。项目政策作为输入，技能保存可迁移的决策流程；不把示例项目、设备或个人路径变成默认规则。

## 确定任务与范围

先判断本轮是方案、创建、更新还是评估。只要求方案/审查时交付结论，不生成或修复文件；授权制作时完成技能及适用验证。已有同职责技能时先检查其消费者和资源，优先修订，保留无关 metadata 和宿主设置。

从用户要求与可读取资料中确认：目标结果、适用/不适用请求、实际输入、已有成功或失败例、工具前提、输出位置、验收标准。仅对会改变技能边界的缺失信息提问；其余可先检查资料并标明假设。任务本身没有重复收益时，说明更合适的文档或脚本，不强行建技能。

用户本轮指令、附件中的内容和参考提示词分开处理。技能不扩大授权，也不自动安装依赖、发布、提交或执行设备控制。输出在用户指定位置；未指定时先查当前项目/宿主约定，不默认写个人全局目录或覆盖同名技能。

## 定边界与资源

读取目标项目适用的 AGENTS 与契约；只把不可稳定推断、会改变决策的信息留在技能中。项目政策由原拥有者维护，避免另一份 conventions、测试政策或组件规范。

写作或参考拆分时读 [authoring.md](references/authoring.md)。

- description 提供能力与触发条件，必要时给易混淆任务的排除条件；正文写输入、步骤、项目约束来源、交付、验证和不适用边界。
- 一个 Skill 围绕一个主要工作流。先写最小正文；长的条件知识放 references，标明何时读取，不要求每次全读。
- 确定且重复的操作才做脚本，说明执行/阅读方式、输入输出、依赖和副作用。只在有可复用产物格式时使用 [最小模板](assets/skill-template.md)，按任务删改，不保留占位内容。
- 实际图片、模型、密钥和案例参数不自动打包；示例与生产源分清，快照有版本与适用限制。
- 通用流程不依赖某个宿主工具名；确有前提时先检测能力，缺失时说明仍可完成的部分。需要跨工具分发时才读 [tool-profiles.md](references/tool-profiles.md)。

## 制作、验证与迭代

创建时先完成核心正文；更新时保留原边界与无关字段，仅修复有证据的问题。不要通过删除合法 metadata、工具前提或项目约束来让检查变绿。

本 Skill 的检查器使用 Python 3.9+ 标准库。从本 Skill 根目录执行：

```text
python -B scripts/validate_skill.py path/to/target-skill
```

它只验证单行字符串 frontmatter 子集、目录命名、显式 Markdown 引用与文件边界，不是完整 YAML/Markdown、技能效果或宿主兼容认证。退出码 0 表示本检查范围通过，1 表示发现错误，2 表示存在未支持写法。复杂 YAML 或宿主字段应保留并用环境已有的相应验证器补证据，不自动装包。引用项目外部政策时需显式声明允许的读取根，例如 `--allow-reference-root path/to/project`；这种技能仍依赖项目上下文。

有脚本或检查器变动时，执行其真实行为测试。需要评估触发或产物时读 [evaluation.md](references/evaluation.md)，按任务成本选择用例。仅更正文案不要求重做全部任务回放。

对新技能或实质变更，至少覆盖应触发、不应触发、近似任务和前提缺失；材料与授权允许时，另用未参与写作的真实输入检查产物。缺少真实输入时完成仍可执行的验证并保留回放缺口，不制造替代素材来宣称真实验收通过。评估权限、资源访问与实际输出，不以模型自评或名称/标题命中代替结果。可使用 [用例](evals/cases.json) 与 [评分标准](evals/rubric.md) 评估本工厂，但这些文件不会自动运行模型。

当复杂技能需要独立行为证据且当前允许委派时，让独立评估者只接触任务、技能和必要原始材料，在隔离目录执行；不提供预期答案或先前结论。没有委派能力时记录缺口，不把自己的复查称为独立验证。

记录失败输入、可观察偏差、原因和最小修订；重放失败及邻近正常场景，并使用新例复核。默认两轮有证据的修订后收敛；仍未解决时交付缺口和下一步，不无限添加通用禁令或循环自评。

## 交付

交付实际文件、触发边界、输入/输出与工具前提；说明新增资源的用途、执行的检查、用例和结果。区分结构检查、元数据选择评估、实际产物验证和宿主原生发现；未运行、缺工具或未验证的兼容性明确列出。

只报告本次结果，保留失败与限制。遵循用户指定的阶段验收，未获下一阶段授权时不继续制作其他技能、安装或分发。
