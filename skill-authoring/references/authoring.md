# 边界与写作

仅在制作/更新正文、设计触发或拆分资源时读取。技能是否有效由任务结果决定，不由文件数量决定。

## 在写文件前作出的决定

| 需要明确 | 判断依据 |
| --- | --- |
| 一个主要任务 | 使用者最终要得到什么；另一类任务是否有独立输入和验收 |
| 触发与排除 | 用真实请求写正例、反例、近似例；不要为提高命中率列全部相关关键词 |
| 输入 | 已知资料、工具、项目政策、已有技能；缺少哪项会实质改变结果 |
| 执行范围 | 当前只设计、创建、修订或评估；文件写入与外部操作是否已授权 |
| 输出与验收 | 具体产物、验证入口、无法完成的情形与停止条件 |
| 知识归属 | 通用步骤留技能，项目政策引用拥有者，案例参数留案例 |

这些决定应覆盖场景、触发、输入、步骤、项目约束、输出、验证、参考与不适用范围，但无需机械地使用九个标题。

## 名称与入口

目录名与 frontmatter 的 name 相同；使用 1–64 个小写英文字母、数字和连字符，不以连字符开头/结尾，不连续使用连字符。description 非空、最多 1024 字符，写能力和何时使用。可引用 [Agent Skills 规范](https://agentskills.io/specification) 核实完整字段。

使用清楚的动词和业务目的，避免与内置同名技能混淆。共享名称不照搬插件 namespace。可选字段只在有明确用途时加入；宿主扩展不是通用权限。

## 渐进加载与资源所有权

- SKILL.md 保存共同决策与流程；references 保存按条件需要的知识，并说明读取条件。
- 脚本减少确定操作的重复实现，不替 Agent 作业务判断；默认不覆盖输入，写输出前检查目标范围。
- assets 是实际被复制/改写的输出材料，不是额外指令层。模板仅作起点，交付前替换占位与无关章节。
- 不为对称创建空目录、README、依赖清单、安装器和重复速查表。先证明需要，再增加。
- 保留用户提供的合法元数据；检查器不支持不能成为删字段的理由。
- 项目契约可能位于技能外；明确依赖当前项目，避免把绝对路径或公司文件打包成通用版本。

工业照片、CAD、学习或软件任务使用同一编写流程，各自重新确定单位、能力、产物和验证；不继承示例的九点、颜色、阈值、文件格式或软件版本。

## 检查器的边界

`scripts/validate_skill.py` 使用 Python 3.9+ 标准库：支持单行、字符串值的 name/description，以及可选 license/compatibility/allowed-tools。普通标量及 JSON 双引号或 YAML 单引号字符串可用；嵌套 metadata、多行标量、别名、复杂引号等返回未支持。它不会把未支持当作通过或擅自重写文件。

引用检查处理 Markdown 的显式 inline 链接与定义式链接，跳过代码块；仅检查本地文件和 Markdown 章节，不抓取外网，不证明所有 Markdown 方言正确。默认不读出技能目录；需要项目政策时用显式 `--allow-reference-root`。不执行目标技能脚本，不扫描凭据或证明内容安全。

退出码和 JSON 中的 errors/unsupported/warnings 要分别保留。对不在检查范围内的格式，用已有工具或人工/宿主验证补证据；不能将完整标准要求降低为本检查器的实现范围。
