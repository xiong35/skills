# 项目与模型契约

只记录当前设备需要的字段，不强行给项目增加一套业务协议。已有模型命名、监测接口和报警色优先复用。

## 资产与坐标

- 记录建模上方向、导出上方向、设备前方、长度单位及尺寸来源。若为照片比例，明确不能用于工程加工。
- 对应节点的坐标要说明是局部坐标还是世界坐标；换上方向后实际重导入比较位置，不只看 JSON 公式。
- 记录 GLB 路径/版本、原始 `.blend` 和重建脚本。导出资源自包含或明确外部依赖，遵循项目 `BASE_URL` 和缓存策略。
- 查看器按真实顶点包围盒适配设备。合并过的倾斜细线、网罩可能有宽大的局部包围盒，不能以此误判设备尺寸。

## 部件、材料与运动

- 每个报警单元对应哪些节点、哪些涂装材料？它们与其他报警单元是否共享同一个材质实例？用实际渲染验证单独变色。
- 转动部件的原点、轴向、轮径比及正负方向来自当前结构。带轮绕轴转，皮带沿路径移动；不可整体旋转闭合皮带环来冒充运行。
- 保留必要的网格分离，细小静态零件可按部件和材料合并。面数/文件大小预算由项目设备数量、硬件和现有模型决定。
- 列表 PNG 作为入口可与详情模型的项目状态色不同。模型材质、色彩空间、灯光及 tone mapping 一起核对，不能只替换 RGB。
- 对实际导入的资产持续推进运动后复查：轴心和固定锚点不漂移，固定壳体不随转子转动，关联部件的方向和速度关系一致。按当前机构选择不变量和观察时长，不要求所有设备都有皮带或动画；示意转速不作为实测 RPM。

## 锚点与动态数据

每个锚点至少记录稳定模型名、所属部件、照片依据、位置不确定性；真实数据绑定另记录设备 ID、测点 ID、指标字段、单位、时间戳和有效条件。模型节点名不等于后端 ID。

标注存在三种不同职责：物理锚点随所属部件确定安装位置；显示点/屏幕卡片负责可读性；真实传感器身份负责数据绑定。调整卡片、投影点或连线路径不能反写物理锚点或真实绑定。点位的画面位置被接受，也不证明不可见端的轴配对或安装坐标已经现场核实。

接入时先查已有卡片、连线、详情与返回的实际消费者，复用其数据、事件、状态和操作，而非只仿外观。根据当前需求明确锚点是否跟随模型、卡片如何定位、遮挡与窄屏如何处理；不把某一次避让算法或固定布局变成通用实现。

从本项目和材料核对以下规则后再实现：

- 报警字段/分级/恢复语义，同一部件多点报警的聚合规则。
- 振动 X/Y/Z 分别是什么方向、是否速度 RMS、单位是否 mm/s；触发条件是任一轴还是组合值，严格大于还是大于等于。
- 取哪些电机端点，缺数据/陈旧数据/断连时如何表现；先沿用现有规则，没有规则时给出明确假设并说明。
- 数据改变时真正更新部件材质和运动状态；运动停止时取消持续帧循环，卸载时释放监听、计时器及 GPU 资源。
- 来自不同接口或指标的采样时刻与接收时刻分别保留；新 HTTP 响应不能刷新旧采样，不以新报警时间证明旧速度有效。缺失/非法时间的处理由接口契约决定，不凭渲染时刻制造新鲜数据。
- 缺接口时的可见空态与模型资源加载失败分开约定。继承项目的空值、提示、报警与认证处理边界，不擅加状态条，也不把局部静默要求扩大到其他设备或全局请求。

可注入测试样本必须明确标记为测试。验证某一测点报警→只改变对应单元、清警→恢复；阈值以下/等于/以上→分别符合规则；缺失和过期样本→符合约定。最后用真实项目组件或端到端页面运行验证，不能只测试纯函数后宣称页面动态已完成。

## 导出检查契约

`scripts/check_glb.py` 的输入为 GLB 2.0。默认拒绝外部资源引用，检查 header/chunk、bufferView/accessor 范围和有限值、网格索引与面数、节点树、锚点名、PBR 参数及要求的材质隔离。它不是完整 glTF 合规验证器，不检查图片解码、着色视觉、真实安装位置或运行时数据绑定。Draco/meshopt 解码不受支持，会以非零退出要求另行检查；其他扩展只列出提醒。

契约是可选 JSON，仅设置本设备有依据的要求：

```json
{
  "required_nodes": ["Motor", "DriveBelt"],
  "anchors": ["Anchor_drive_end", "Anchor_non_drive_end"],
  "min_triangles": 1,
  "max_triangles": 120000,
  "materials": {
    "motor-paint": {
      "baseColorSRGB": "#258ba0",
      "metallicFactor": 0.7,
      "roughnessFactor": 0.4
    }
  },
  "independent_paint_groups": ["Motor", "Gearbox"],
  "allowed_shared_materials": ["steel", "rubber"]
}
```

`required_nodes` 和 `anchors` 要求各名称在节点数组中恰好出现一次；没有指定数量限制。`materials` 按材质名匹配，`baseColorSRGB` 为六位 sRGB 色值，脚本转换为 GLB 线性色比较；也可直接提供四项 `baseColorFactor`。`independent_paint_groups` 要求各节点子树除允许共享项外至少使用一种材质，并且这些材质索引互不共享；它验证资产所有权，仍需在查看器中验证变色逻辑。面数统计包含资产中的所有网格、支持 TRIANGLES/STRIP/FAN；实例不会重复计数。退出码 0 为该检查范围通过，1 为资产/契约失败，2 为未支持的压缩编码或命令错误。

自检：`python scripts/test_check_glb.py`。测试会生成最小有效模型及坏头、越界索引、NaN 等反例，验证错误输入通过 CLI 非零退出，不依赖本案例资产。

格式依据：[Khronos glTF 2.0 规范](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc)。正式交付仍运行适用的 Khronos Validator 和实际导入/渲染。
