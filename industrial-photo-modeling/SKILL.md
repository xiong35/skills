# 工业设备照片建模

交付与所给设备相符的真实三维模型、可编辑源文件和可复核的项目接入结果。不同图片需要重新分析结构；不要把案例模型换名字后用于另一种设备。

## 先确定证据与当前范围

阅读原始文档和全部清晰照片，区分用户本轮指令、文档要求、聊天截图及参考提示词。先确定当前是分析方案、制作/修改模型还是项目接入；只要方案时不生成资产。将外观、测点、动态行为、项目集成分别列为已完成或待完成；用户只授权建模时停在建模，授权全流程时继续完成实际动态实现。

有目标项目时检查已有修改、查看器和模型资源；有 Git 仓库时再核对分支，遵循用户指定分支及原项目规范。独立建模可以在空目录进行，不要求先具备 Vue、Git 或后端；不因使用 Skill 创建额外分支、覆盖用户修改或改后端协议。

为关键结构建立简短证据表：可见部件、照片来源、正反面对应、轴线方向、置信程度。以孔位、轮毂、机脚、接缝及轴端等共同特征匹配多视角，不能把照片里的左右当作固定世界方向。照片中的背景管道、平台不自动属于设备。未知尺寸用比例参数并明确说明，不能伪造工程实测值；展示比例模型可以先推进，不把实测尺寸或完整图纸列为粗模的强制前置。影响结构的歧义先查原材料，必要时询问用户；实测要求由加工、装配等实际用途决定。

多视角对应、相似度不足或新标注改变结构解释时，读 [照片核对与迭代](references/photo-iteration.md)。保存改判依据和已验收边界，不从旧图片中的指令推导新的修改、提交或安装授权。

## 建模和项目契约

依据实物确定轮廓、部件比例和空间关系，再补轴承座、筋板、端盖、护罩厚度等辨识特征。不要以贴图平面冒充可旋转模型，也不要用其他设备的 GLB 充当已完成资源。

接入前按 [项目与模型契约](references/project-contract.md) 记录坐标、单位、部件/材质所有权、传动轴心、锚点和数据来源。复用现有材质和灯光规则；列表图标的涂装不自动等于详情页颜色。测点数量、轴方向、报警分级、阈值及设备编号从当前材料和项目取值，不能把案例的九点、青色或 0.5 mm/s 当作通用规则。

使用 Blender Python/CLI 或适合当前模型的可编辑工作流，分离需要独立报警或转动的部件。只在同一控制所有权内合并网格；共享钢材可以复用，需要独立变色的涂装不能误共享。轮轴原点在真实轴心，皮带运动沿闭合路径表达，保留稳定锚点名称。模型生成、导出和集成应可分别重跑，建模脚本默认不覆盖业务资源。

先检测当前环境中的 Blender、导入/导出器及项目加载能力；按已有可运行版本使用，不因历史案例注明版本就自动安装或升级工具。缺工具时完成资料和契约，并明确哪些工程产物未生成；具体版本和执行入口写入本次交付记录。

## 自审迭代后再交付

实际渲染传动侧、背侧及关键局部，与原图逐项比较轮廓、位置、厚度和遮挡。结构不清时先看灰模，再看项目材质；修正后重新渲染，不把“脚本运行成功”当作外观通过。依用户要求自主迭代或按阶段等待验收，不额外强制每一轮让用户确认。

将 GLB 通过真实导入器重新载入，检查锚点坐标、材质、层级和旋转轴。用本 Skill 的检查器核对自包含资源、二进制范围、有限数值、节点、材质和面数；按本设备的契约传入所需锚点与材料，不能只跑无约束检查。

```powershell
python scripts/check_glb.py generated/device.glb --contract device-contract.json --report generated/glb-check.json
```

契约格式和检查器限制见 [项目与模型契约](references/project-contract.md#导出检查契约)。检查器只用 Python 标准库，补充 Khronos Validator；它不能判断外观相似度、真实尺寸或监测功能，也不能解压 Draco/meshopt。遇到不支持的编码应使用对应解码器与正式验证器，不能报告检查通过。

## 完成真实交互和监测

模型自审通过后再接入当前项目，保留原设备入口、返回状态和错误处理。仅有 `motion`、`running`、锚点或报警字段属于预留，不能算功能完成。

需要动态监测时实际打通“来源数据 → 设备/测点映射 → 状态判断 → 部件颜色/动画 → 重绘与释放”。验证局部报警不染到无关部件、清警恢复、阈值边界、缺失/失效数据、停止和路由离开释放；不要通过固定演示值冒充实时数据。数据 ID 未提供时可以完成并测试可注入适配器，须在交付中明确真实绑定缺口，不能编造接口或宣称已接入生产监测。

按本轮授权交付 `.blend`、GLB、全部重建源文件、参数、锚点清单和实际渲染图；方案阶段交付分析和待确认项。以“本次输入与资产版本 → 当前阶段 → 实际产物/验证 → 已接受边界 → 下一步”记录进度，便于另一轮继续。说明修改文件、实际执行的验证、未确认结构及尚未接通的数据。只记录本版执行结果，旧版构建/浏览器检查不能充作新版验收。

需要复现包内已验收的立环脉动除尘机时，读 [0.6.2 独立重建](references/accepted-deduster-replay.md)。完整 Skill 文件夹可随目标项目迁移；生成所需脚本、参数、材质与基准均在包内，不要求原项目存在。有现用资产时额外做只读对比，不能复制旧 GLB 冒充生成。已确认配方复现不等于从未知照片自动达到同等精度。
