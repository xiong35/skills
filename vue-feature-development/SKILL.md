# Vue 功能开发

交付融入现有项目的功能，并说明复用与新增的依据。先理解已有能力的实际契约，再选择实现；避免为一个局部需求建立另一套同职责机制。

## 定位需求和已有实现

确认本轮目标、预期行为、允许改动与验收方式。用户只要方案时给出方案；已授权实现时继续完成代码和验证。常规技术选择自行处理，只有会改变业务含义或实现范围的缺失信息才询问；保留用户指定的阶段验收。

读取当前项目适用的 AGENTS、运行入口和相关模块约定，核对分支、工作区与已有改动。处理 inspect-frontend 时按 [项目定位参考](references/project-context.md) 查源码；在其他 Vue 项目重新定位入口，不套用该仓库的路径、栈或业务参数。

沿“用户入口 → 页面/组件 → 状态与数据来源 → 公共能力及消费者”读必要代码。搜索功能词、显示字段、接口函数和组件引用；读取候选实现及至少一个实际调用点，不能只凭文件名或截图决定重写或复用。核对自动导入、全局注册和项目已有依赖，避免重复创建基础能力。

## 作出复用与所有权决定

对本次需要的能力比较输入输出、事件、样式/布局、空态、权限和资源生命周期；按任务只检查相关项。

| 现有能力与需求的关系 | 采取的动作 |
| --- | --- |
| 已满足同一契约 | 直接使用，保留有效零值及已有兜底 |
| 现有参数、插槽或组合可满足 | 做局部适配，把新增状态留在其拥有者 |
| 需要扩展共享行为 | 最小扩展，检查实际消费者及兼容性 |
| 没有适用能力或所有权确实不同 | 新增局部实现，说明具体差异与替代方案的代价 |

旧能力嵌在业务页面里时，比较有限提取、组合适配与局部实现的成本；不把整页复制成公共组件，也不为复用一小段逻辑迁移无关模块。历史代码仅作为事实和候选，已知缺陷或过时 API 不机械继承。

组件归属按谁使用、谁维护状态和谁释放副作用确定。页面独有的查询/表单会话通常由页面拥有；受控组件通过 props/events 与父级协作。异步数据、弹窗草稿、订阅和渲染资源分别确认切换、取消及卸载行为，避免同一状态出现多个写入源。

数据适配沿现有 API、请求器和状态方案。读取真实响应形状及其消费者；上游已保证的格式不在每层重复归一化。额外校验、请求包装或兜底须对应实际契约差异；接口缺失时按本轮约定完成可做部分，列出缺口，不编造生产数据或改动公共请求来掩盖缺失。

## 实现与验证

在目标模块完成必要修改。复用已有组件的行为和样式，保留权限、返回状态、空态与事件语义；不为独立试验重建公共能力，也不把试验规则推广到其他模块。

根据改动及现有项目的验证入口选择检查：交互和布局看真实浏览器；数据看响应、零值、缺测与晚到结果；共享组件看受影响消费者；副作用看取消、关闭、返回和重入。测试和构建按项目已有工具执行，不在 Skill 维护另一份命令或版本政策。

最后复查 diff 中新增的组件、函数、封装、分支和文件：能否直接使用已查明的能力，新增部分是否仍有明确职责。实际授权要求实施时，不以复用清单或方案代替代码完成。

## 交付与评估

说明实际改动、复用位置、新增/扩展的必要性、执行的验证与缺口。小改动用简短说明；多个复用决策可用“需求 → 旧实现 → 选择与原因”的小表，不强制新增报告文件。

本 Skill 引用项目政策，不维护第二份编码规范。提交、推送、安装和下一阶段工作仍按当前授权执行。

评估使用 [任务用例](evals/cases.json)，分别核对是否适用、实际取舍、改动范围与结果。用例不会自动调用模型，结构校验不能证明开发效果；回放放在隔离目录，避免为验证 Skill 改动生产业务。
